# show_dance 相册磁盘缓存

首次进入页面且尚未保存缓存位置时，自动显示“设置磁盘缓存”对话框。点击选择硬盘目录完成浏览器授权，或选择浏览器磁盘缓存继续；选择完成前不下载模型。之后进入页面自动选择第一个视频，只按已保存的位置依次缓存该视频的所有片段；切换视频时终止旧视频未完成的下载，保留已完成文件，转为顺序缓存新视频。卡片展示状态和进度，相册底部展示按字节加权的总进度。“缓存管理”可暂停、恢复、重试、更换存储位置和强制清理。

## 存储位置

- 默认：当前网站来源的 OPFS 下 `show-dance-album-v1/`，文件实际由浏览器存于磁盘，不是 HTTP 缓存或内存中的 Blob 列表。域名、协议、端口不同的页面不共享数据。
- 普通硬盘目录：在管理面板点击“选择硬盘目录”，通过浏览器文件夹选择框授权；仅在所选文件夹内创建 `show-dance-album-v1/`。不使用 Node/Python 后端。该能力通常需要桌面 Chrome/Edge、HTTPS 或 localhost。
- 选择普通硬盘目录后，将目录句柄保存到 IndexedDB `show-dance-preferences-v1/settings` 的 `directory` 键（不保存模型数据）。刷新优先复用此目录；权限失效时暂停并显示授权按钮，用户点击后请求读写权限，不自动退回 OPFS 重复下载。首次使用尚未选择目录时显示设置对话框；取消系统目录选择器仍停留在设置界面，可重新选择。
- “使用浏览器磁盘缓存”将目录偏好记为 `opfs` 并切回 OPFS；“强制清理当前缓存”只删模型，不删目录偏好。清除本站浏览器数据会同时清除目录偏好，但普通硬盘目录里的文件保留，可重新选择复用。切换位置不迁移或删除原位置。
- OPFS 受本站配额和浏览器数据清理规则约束，管理面板可申请持久存储并显示实际授权结果。持久存储不能阻止用户手动清除网站数据。普通目录不属于网站配额，磁盘不足、撤销权限、移动文件均会显示写入或读取错误。

## 大文件与网络

单路 FIFO 异步网络流写盘，通过 WritableStream 反压，每块写完后继续读取；不先拼接完整 ArrayBuffer/Blob，也不通过多个 Worker 复制大文件。播放和自动缓存共用队列，正在缓存的模型点击后等待同一下载任务。当前视频的全部文件逐个解码并常驻系统内存，每个文件内部全部 GPU 段依次预建并保持驻留，不再淘汰已播放文件。切换视频或强制清理时统一释放。若显存预算不足或分配失败，停止继续预读并记录错误，已有场景继续播放；不将失败段标绿，也不静默回退为仅磁盘缓存。后台场景隐藏但保持尺寸，目标帧实际绘制后才切换；首段常驻，下一段尚未读取完成时回到首段循环。首次片段就绪后自动播放。普通下载、读取和错误只显示右下角单行日志，不弹出中央提示或打断当前画面。

进度条按片段显示绿色（已读入内存/显存并完成目标帧绘制，且场景仍驻留）和黄色（尚未预读就绪或已经释放）；黄色位置拒绝点击/拖动跳转，磁盘下载完成不改变该颜色；绿色位置只在仍驻留的场景中定位并等待绘制后切换。文件下载进度独立显示在相册底部和工作日志。相邻文件共享边界帧仍仅播放一次。清理/目录首次授权与主动打开的缓存管理仍使用原交互。

网络依赖仅为同站相册清单、缩略图和模型静态资源，无外网模型或后台服务。当前 `dance` 视频为 12 个文件、855,601,448 字节、0–1079 帧。源文件未记录帧率，沿用播放器默认 30 fps，可在 `video.json` 中指定。

缓存命中不请求模型资源；本功能不提供整个网站的离线启动（HTML、JS、字体、清单和缩略图仍需可访问或由浏览器自行缓存）。文件无需断网时重新下载。

## 完整性与版本

键为 `[schema=1, gallery.updatedAt, assetUrl, fileBytes, codec]` 的 SHA-256，分别保存 `<key>.4cgs` 和 `<key>.json` 完成标记。完整关闭文件、核验字节长度后才写标记。读取时再次核对身份与长度。此 SHA-256 是缓存键摘要，不是模型内容校验和；相册生成脚本将各文件清单（含流校验和）的摘要纳入 `updatedAt`，替换文件后必须重新生成相册清单。版本升级写新键，不在新下载失败时破坏旧版本。旧版本由显式清理回收。

下载失败/取消会中止写入并尝试删除半文件。意外关闭页面可能留下未完成文件，但无有效完成标记的文件不会作为缓存命中。Web Locks 可用时跨标签页同文件写入互斥，清理等待文件任务退出。

## 清理

“强制清理当前缓存”停止当前页面播放、终止并等待下载，再移除当前专属目录中符合缓存命名格式的模型和标记。不会清空其他 OPFS 数据或用户普通目录中的其他文件。其他存储位置须切换后分别清理。

清理后当前页面暂停自动缓存，点击“恢复缓存 / 重试”重新下载；重新打开页面仍按默认自动缓存策略运行。正在其他标签页打开同一相册时，建议先关闭其他页面，避免它们再次下载。清理失败会显示错误，不会谎报成功。

## 独立视频相册与更新

show_dance 只读取 `4cgs_show/gallery.json`，编辑器的 `4cgs/gallery.json` 保持独立。每个 `public/4cgs_show/<视频目录>/` 包含顺序片段 `.4cgs` 与 `thumbnail.webp`。当前 dance 缩略图来自首段真实渲染画面。

新增或替换片段后运行 `node scripts/build-show-gallery.mjs`，该开发期脚本仅读取容器头部，按 firstFrame 排序并校验连续性。可选 `video.json` 指定 name、description、tags 和 fps；每个新目录需保存其真实渲染的 `thumbnail.webp`。运行时纯前端读取静态清单和文件，无需此脚本或额外服务。之后按项目规则更新版本并运行 `npm run build`，发布到 docs。

### 播放与后台线程

- 下载、流式磁盘写入、长度验证和缓存命中检查运行在 `show-dance-download` Worker；主线程只接收 File 与缓存状态。目录权限和持久化授权仍在用户手势所在的窗口完成。缓存目录、键、清理入口与离线复用策略不变。
- 4CGS 解压最多两路 Stream Worker，属性解码在独立解码 Worker 顺序完成；Canonical 展开使用 CPU Worker，不额外占用 GPU Compute；RAW4D Loader 只开一条提取流水线。
- 颜色、变换、SH 和时间纹理在 `show-dance-texture-preparation` Worker 打包，每批最多 4096 点，时间轨道按属性数进一步缩小批量。共享缓冲只传视图，非共享缓冲只复制当前小块；返回值使用 Transferable。编辑器默认保留原执行模式。
- 主线程保留播放、交互及图形设备提交。GPU 纹理逐张让出绘制机会，后台隐藏场景首帧确认后停止连续绘制，切换时恢复。取消加载时终止准备 Worker。
- 播放用独立 rAF 截止时钟，缓存/读取进度更新不会重置时钟；只在上一帧真正显示后推进，未就绪时不跳帧追赶。
- 页面显示渲染循环 FPS 与帧耗时，二者不代表视频内容帧率。线程隔离不能消除共享内存、GPU 带宽、纹理上传与驱动资源竞争，也不能解决物理内存不足；不得把线程分离表述为所有设备上零掉帧。
